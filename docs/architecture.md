# Архитектура

Требования — в [brief/MASTER_PROMPT.md](brief/MASTER_PROMPT.md). Здесь — принятые решения и почему. Новые решения добавляются в журнал внизу.

## 1. Один публичный репозиторий

Бриф (0.1) допускает один репозиторий или пару публичный + приватный. Выбран **один публичный** `DenisHumen/krokosha-site`.

- **Витрина.** Для инженера инфраструктуры открытые `install.sh`, конфиги Nginx/systemd и Go API — само по себе портфолио. Репозиторий попадёт в собственный блок «Проекты».
- **Проще эксплуатация.** Одна копия на VPS, не нужен deploy key, один CI. Изменение дизайна и интеграции проходит одним PR.
- **Защита веток.** На бесплатном плане GitHub защита веток (main только через PR + обязательный CI) работает только в публичных репозиториях.
- **Безопасность не зависит от закрытости кода.** Секреты лежат только в `/etc/krokosha/env` (600, root:krokosha), в репозитории — `deploy/env/.env.example`. Путь админки задаётся при установке. Пароли хранятся в argon2id, есть rate-limit и fail2ban.
- **Цена решения.** Claude Design видит код бэкенда (безвредно). Эвристики антиспама открыты, но основная защита — ALTCHA и rate-limit, которые от этого не слабеют.

Если позже понадобится закрыть бэкенд: `api/` и `deploy/` выносятся в приватный `krokosha-infra`, названия каталогов не меняются (C1).

## 3. Поток данных

```
content/*.yaml ──┐
                 ├─► krokosha-sync (Go, таймер 6 ч) ─► content/generated/*.json ─► astro build ─► releases/<ts> ─► симлинк current
GitHub API ──────┘      • репозитории + tier (docs/contract.md §5)
                        • аватар → AVIF/WebP
                        • experience_years от career_start
                        • ETag + кэш: при ошибке GitHub сборка из кэша, stale=true
```

Стаж считается при каждой сборке, а не кроном «раз в год». Сборка идёт каждые 6 часов, поэтому число обновится само в нужный день (B4).
