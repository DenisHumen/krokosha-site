# Архитектура

Требования — в [brief/MASTER_PROMPT.md](brief/MASTER_PROMPT.md). Здесь — принятые решения и почему. Новые решения добавляются в журнал внизу.

## 1. Один публичный репозиторий

Бриф (0.1) допускает один репозиторий или пару публичный + приватный. Выбран **один публичный** `DenisHumen/krokosha-site`.

- **Витрина.** Для инженера инфраструктуры открытые `install.sh`, конфиги Nginx/systemd и Go API — само по себе портфолио. Репозиторий попадёт в собственный блок «Проекты».
- **Проще эксплуатация.** Одна копия на VPS, не нужен deploy key, один CI. Изменение дизайна и интеграции проходит одним PR.
- **Защита веток.** На бесплатном плане GitHub защита веток (main только через PR + обязательный CI) работает только в публичных репозиториях.
- **Безопасность не зависит от закрытости кода.** Секреты лежат только в `/etc/krokosha/env` (600, root:krokosha), в репозитории — `deploy/env/.env.example`. Путь админки задаётся при установке. Пароли хранятся в argon2id, есть rate-limit и fail2ban.
- **Цена решения.** Claude Design видит код бэкенда (безвредно). Эвристики антиспама открыты, но основная защита — ALTCHA и rate-limit, которые от этого не слабеют.

Если позже понадобится закрыть бэкенд: `api/` и `deploy/` выносятся в приватный `krokosha-infra`, названия каталогов не меняются (C1).

## 3. Поток данных

```
GitHub API ──► krokosha-sync (Go, таймер 6 ч) ──► content/generated/github.json   репозитории + tier (contract.md §5)
                  • ETag + кэш: при ошибке GitHub            content/generated/avatar.*     аватар как есть, без конвертации
                    отдаётся прошлый ответ, stale=true
                                                                       │
content/*.yaml ────────────────────────────────────────────────────────┤
                                                                       ▼
                                          astro build (web/)  ─► releases/<ts> ─► check-dist ─► симлинк current
                                            • схемы YAML, языки, склонения
                                            • experience_years от career_start
                                            • аватар → AVIF/WebP (sharp)
                                            • SEO: hreflang, JSON-LD, sitemap.xml, CSP
```

Разделение обязанностей: **sync только ходит в GitHub**, всё остальное делает сборка. Так `web/` собирается без Go (CI, локальная разработка, превью дизайна): если `content/generated/github.json` нет, берётся снимок репозиториев из `mock/en/projects.json`.

Стаж считается при каждой сборке, а не кроном «раз в год». Сборка идёт каждые 6 часов, поэтому число обновится само в нужный день (B4). «Сегодня» берётся в часовом поясе владельца (`site.yaml → timezone`), а не сервера.

Формат `content/generated/github.json` — часть `projects.json` из контракта: `{ "public": [...], "syncedAt": "…", "stale": false }`. Схема — `web/src/lib/schema.ts → githubDataSchema`; сборка отклонит файл с неизвестным `tier` или ссылкой не `http(s)://`.

## 5. Сервер и ограничения установщика

Проверено на VPS 2026-09-18.

| Параметр | Значение | Следствие |
|---|---|---|
| ОС | Ubuntu 24.04.5 LTS, KVM | целевая ОС `install.sh` |
| CPU / RAM / swap | 2 vCPU / 1.9 ГБ / 2 ГБ | Astro-сборка — с `NODE_OPTIONS=--max-old-space-size`; почта — docker-mailserver **без ClamAV**, Rspamd включён; webmail (Q9) — нет, Mailcow не влезет |
| Диск | 28 ГБ, свободно 21 ГБ | 3 релиза сайта + почта + логи 30 дней помещаются; ротация обязательна |
| Сеть | 2 IPv4 на `eth0`, IPv6 нет | AAAA-записи не публикуем; nginx и почта слушают основной IPv4 |
| Исходящий 25/tcp | открыт | прямая доставка почты без relay |
| PTR | не выставлен | Выставляется **у хостера VPS, а не в DNS домена**: обратная зона `147.175.46.in-addr.arpa` обслуживается `ns1–ns4.s-host.com.ua`. Нужно значение `mail.krokosha.xyz` — через кабинет S-Host или тикет, до запуска почты |
| DNS домена | NIC.UA (`ns10–ns12.uadns.com`). Есть: A для `@`, `www`, `mail` → IP сервера; MX 10 `mail.krokosha.xyz`; лишний шаблонный CNAME `ftp` | SPF, DKIM, DMARC и autoconfig добавляются при установке почты — список выведет `install.sh` |
| Уже работает | WireGuard `wg0` (UDP 51820), `ip_forward=1`, NAT для VPN-подсети | **установщик не должен это ломать** (см. ниже) |
| SSH | вход только по ключу, root по SSH запрещён — `/etc/ssh/sshd_config.d/10-krokosha-hardening.conf` | до этого было ~22 тыс. попыток подбора пароля в сутки; `install.sh` поддерживает этот файл идемпотентно |

Правила для `install.sh`, вытекающие из этого:
- Не трогает сторонние сервисы. Дополнительные входящие порты передаются параметром (на этом VPS — `--allow 51820/udp`), UFW включается только после того, как все они добавлены.
- Не выключает `net.ipv4.ip_forward` и не сбрасывает существующие правила nftables/NAT. Для UFW: `DEFAULT_FORWARD_POLICY` и маршрутизация VPN-подсети сохраняются.
- Перед включением UFW проверяет, что правило для SSH уже есть, чтобы не отрезать доступ.
