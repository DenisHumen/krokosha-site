# Передача: выкатка и проверка ветки `claude/beautiful-noether-rz8lrd`

Для агента с браузером (и с SSH к серверу, если его дадут). В документе нет секретов: путь админки, пароли, токены и доступы спросить у Дениса и не записывать ни сюда, ни в PR.

Админка и личный кабинет — в третьем дизайне (v3): чёрная панель разделов слева, шапка со строкой показателей, плитки. Остальные страницы сайта не менялись.

## 1. Что в ветке по сравнению с `main`

- **Личный кабинет клиента** (`/account/`, `/uk/account/`, `/ru/account/`): вход по шестизначному коду на почту или через бота, без паролей. Один человек — один кабинет. Если привязать к кабинету почту или Telegram, которыми уже входят в другой кабинет, кабинеты объединяются (заявки, контакты, ачивки). Привязка завершается только кодом в том же браузере: ссылки для неё нет.
- **Скидки**: приветственная 10 %, разовая 20 % за все пасхалки, уровни Silver/Gold/Platinum, персональная от владельца; действует наибольшая. Персональная скидка достаётся только заявке, отправленной с входом в кабинет.
- **Ачивки**: редкость как в Steam, ачивки за заказы, звуки.
- **Админка**: клиенты (скидки, суммы, объединение, ссылка для входа), статистика ачивок, «Почта» (ящики сотрудников).
- **Telegram**: ответ свайпом на уведомление, длинные ответы частями, предупреждение, что клиент заблокировал бота. Ссылка в бот для клиента видна в карточке заявки, а ответ идёт туда, куда обещал бот. Сообщения людей без заявки приходят сотрудникам. Перезапуск сервиса не теряет принятые сообщения. Подробно — [telegram.md](telegram.md).
- **Дизайн v3**:
  - админка — все экраны;
  - кабинет — вход и шесть экранов: главная, заявки, новое обращение, скидка и уровень, ачивки, профиль. Экран выбирается адресом: `#requests`, `#K-0042`, `#new`, `#loyalty`, `#achievements`, `#profile`. Ссылки из писем и бота на `…/account/#K-…` открывают заявку, как раньше.
- **Быстрые ответы** ([quick-replies.md](quick-replies.md)):
  - пул шаблонов на трёх языках (миграция `0018` добавляет 15 на язык, тексты владельца не трогает);
  - карточка заявки сама поднимает три подходящих к разговору шаблона и объясняет почему; остальные — списком с фильтром;
  - шаблоны складываются в один ответ, к шаблону можно прикрепить фото, видео и документы;
  - файлы доходят до клиента: в Telegram — альбомом, письмом — вложениями до 15 МБ, в кабинете — в переписке. Бот предлагает шаблоны в том же порядке и отправляет их файлы.
- **Статус системы**: кнопка «Бэкап сейчас» и число блокировок fail2ban.
- **Бот**: роль «только уведомления» (карточки без кнопок); доступ по Telegram ID выдаётся из админки.
- **Иконка сайта для Google**: `favicon-96.png` и `favicon.ico` (раньше Google показывал в выдаче глобус).
- **Безопасность** (проверка 2026-09-24):
  - сборка сайта (сторонний код npm) больше не может записать то, что потом выполняет root, и не видит секретов;
  - root-скрипты не пишут по именам в каталогах пользователя сайта;
  - хелпер ящиков сравнивает адреса как строки;
  - логин админки проверяется до базы;
  - CSV обезврежен и для Excel с `;`;
  - секреты не попадают в журнал API;
  - fail2ban не обходится строкой запроса.

  Подробно — `git log main..claude/beautiful-noether-rz8lrd`.

## 2. Перед выкаткой: CI

1. Открыть PR `claude/beautiful-noether-rz8lrd` → `main` (если его нет) и дождаться CI: задания **web**, **api**, **deploy**.
2. Задание **deploy** — настоящая установка на чистой Ubuntu 24.04 (`deploy/ci/test-install.sh`). В ветке менялись установщик, юнит сборки и root-скрипты. Локально полный тест прогнать не удалось: песочница разработчика не пускает к `go.dev`, а Docker Hub отвечал 429. Особенно важны проверки:
   - `the build left its report`, `the «rebuild now» button…`: сборка в новой, более узкой песочнице;
   - `the build may write web/ of the repository, not the rest of it`, `…nor read the files of requests`;
   - `the API's environment is root's to read, not its own user's`;
   - `…not even as «lead.@»`: ящик `leads@` не удаляется «похожим» адресом;
   - `…writes its report as the site user, not through a link the site user put there`;
   - `fail2ban recognises the failed logins`;
   - `the icon for Google Search is a PNG`, `favicon.ico is served`;
   - `a template takes a file bigger than a form, through nginx`, `the rest of the admin area still takes small forms only`: новый location nginx `…/upload/` для форм с файлами.
3. Задание **api** на машине разработчика не проходило в одном тесте — `sysstatus/TestCollectReadsWhatTheBuildLeft`. Причина в самой машине (диск был «заполнен на 91 %»); в CI тест должен пройти. Если он упадёт и в CI с другой причиной — это ошибка, прислать лог.
4. Красный CI — не выкатывать, прислать лог упавшего шага.

## 3. Выкатка

1. Смержить PR в `main`. Или, если Денис хочет выкатить ветку до слияния: `REPO_BRANCH=claude/beautiful-noether-rz8lrd` в `/etc/krokosha/env`.
2. На сервере: `sudo /opt/krokosha/repo/deploy/update.sh`. Вывод заканчивается итогом установки; ошибка — красная строка `ERROR:`.

При этом обновлении на сервере меняется:
- юнит сборки `krokosha-sync.service` пишет только в `web/`, `content/generated`, кэши npm и GitHub, `status/`, `requests/`, `/var/www/krokosha`; появляется drop-in `krokosha-sync.service.d/data-dir.conf`;
- каталог `/var/lib/krokosha/mail` переходит к пользователю `krokosha`: хелпер ящиков пишет туда от его имени;
- отчёты `status/backup.json` и `status/certwatch.json` после ближайшего запуска принадлежат `krokosha`;
- API и CLI при старте становятся недампируемыми: их `/proc/<pid>/environ` читает только root;
- очередь доставки делает девять попыток за двое суток вместо восьми за 21 час;
- nginx: формы с файлами в админке идут на `<ADMIN_PATH>/upload/` (до 110 МБ), лимит 64 КБ перенесён из сниппета `krokosha-admin.conf` в каждый location админки;
- миграция `0018`: поля шаблонов, файлы шаблонов, `telegram_uploads`; в таблицу шаблонов добавляются 45 новых (15 на язык).

## 5. Проверка на сервере (если есть SSH)

```bash
systemctl show krokosha-sync.service -p ReadWritePaths          # без /opt/krokosha/repo целиком
sudo systemctl start krokosha-sync.service && cat /var/lib/krokosha/status/sync.json   # "ok":true
sudo stat -c %U /proc/$(systemctl show -p MainPID --value krokosha-api.service)/environ   # root
stat -c '%U %a' /var/lib/krokosha/mail                           # krokosha 750
sudo krokosha-mailbox list                                       # leads@… на месте
sudo /opt/krokosha/repo/deploy/backup.sh && stat -c %U /var/lib/krokosha/status/backup.json   # krokosha
sudo fail2ban-client status krokosha-admin
```

## 6. Google Search Console и Bing

1. [search.google.com/search-console](https://search.google.com/search-console): ресурс `krokosha.com` должен быть подтверждён (тип «Домен», TXT-запись в DNS; подробно — `deploy/README.md`, раздел «Поисковики»). Если нет — подтвердить и добавить `https://krokosha.com/sitemap.xml`.
2. «Проверка URL» → `https://krokosha.com/` → «Запросить индексирование». Это ускоряет и появление иконки: Google обновляет иконки сам, от нескольких дней до недель.
3. Что Google уже взял как иконку: `https://www.google.com/s2/favicons?domain=krokosha.com&sz=96`. Глобус там — иконку ещё не обработали.
4. Старый домен `krokosha.xyz`: если оба ресурса подтверждены — в настройках ресурса `krokosha.xyz` → «Изменение адреса» → `krokosha.com`. Тогда результаты старого домена (без иконки) уйдут из выдачи быстрее.
5. Bing Webmaster Tools — «Site Move» так же. IndexNow бинг получает сам после каждого релиза.

## 7. Что решает Денис (кодом не закрыть)

- **Скидки можно «нафармить» новыми адресами.** Пасхалки находятся в браузере, поэтому их может «найти» и скрипт. Приветственные 10 % тоже получает каждый новый адрес. Сервер не может доказать, что человек новый. Сейчас защита одна: владелец видит причину скидки в карточке и решает сам. Как вариант, давать скидку за пасхалки только с входом в кабинет.
- **Обновление всё ещё запускается из рабочей копии пользователя сайта** (`update.sh` → `install.sh`). После исправлений ни один его процесс в песочницах systemd туда писать не может. Полная развязка: репозиторий, принадлежащий root, и отдельный пользователь для сборки. Это отдельная переделка установщика.
- **Telegram:** главная кнопка сайта ведёт в личный Telegram мимо системы; бот принимает только текст; нет назначения заявок сотрудникам. Подробно — [telegram.md](telegram.md), раздел 7.
- **Резервная копия на другой машине** (`BACKUP_RSYNC_TO`) везёт секреты открытым текстом. Туда нужна доверенная машина или зашифрованное хранилище (`deploy/README.md`, «Резервные копии»).
