# Дорожная карта

Что сделано, что дальше и в каком порядке. Обновляется в каждом PR, который закрывает пункт.
Решения и их причины — в [architecture.md](architecture.md), требования — в [brief/MASTER_PROMPT.md](brief/MASTER_PROMPT.md).

**Правила этапа** (решения Дениса от 2026-09-18):

1. На VPS ничего не выкладываем, пока бэкенд не реализован **полностью**.
2. Проверяем локально в Docker: `deploy/docker/staging/staging.sh up` → `https://krokosha.localhost`.
3. Дизайн — после бэкенда (Claude Design работает в `design/` по [design/CLAUDE_DESIGN_PROMPT.md](design/CLAUDE_DESIGN_PROMPT.md)).
4. Хранилище — MySQL + Redis в Docker, все данные в одной директории `/srv/krokosha`.

## Бэкенд — в работе

**Готовность бэкенда: 56%** (шаги 1–4 и 5a). Веса шагов: основа 10 · аналитика 12 · админка 18 (вход 8 + экраны 10) · трафик и статус 8 · заявки 20 (приём 8 + админка 9 + вложения 3) · бот 16 · почта 10 · эксплуатация 6.

Каждый пункт — отдельный PR с тестами; после каждого стенд должен подниматься одной командой.

- [x] **1. Основа API.** `krokosha-api`: конфигурация, MySQL (миграции), Redis с деградацией в память, HTTP-сервер, `/api/health`, systemd-юнит, прокси в nginx. Установщик: Docker, контейнеры MySQL и Redis с лимитами памяти, корень данных `/srv/krokosha`, генерация секретов. CI: MySQL и Redis как сервисы. Замер на стенде: MySQL 132 МБ, Redis 4 МБ.
- [x] **2. Аналитика** (B5). `/api/e`: проверка схемы, дневная соль, усечённый IP, отсев ботов, DNT/GPC, лимиты. `analytics.js` < 3 КБ, читаемый. События: просмотр, глубина скролла, секции, клики по `data-track`, внешние переходы, время на странице, UTM. Страница `/privacy` сверяется с реализацией. Сделано: скрипт 2,9 КБ gzip; тест ищет IP и User-Agent во всех таблицах и ключах Redis — их там нет. Гео по IP — в шаге 8.
- [x] **3a. Админка: вход** (B6). Секретный путь (`--admin-path` или случайный), argon2id, сессии в cookie `__Host-`, CSRF, TOTP с QR-кодом, список сеансов, журнал действий. Лимит попыток в API, отдельный лимит nginx на форму входа, fail2ban по логу админки. `krokosha-cli admin list|create|passwd|disable|enable|totp-reset`; установщик создаёт первого администратора (пароль без эха или из файла).
- [x] **3b. Админка: обзор, визиты, экспорт** (B6). Обзор по ref-03: таймлайн (часы или дни, реклама отдельным цветом), «сейчас на сайте», живая лента (SSE), секции по времени и охвату, прокрутка, кольца конверсий, источники, кампании, страницы, языки, клики, устройства, страны; период — день, неделя, месяц, свой диапазон. Визиты: путь посетителя по секциям и кликам. Экспорт CSV, безопасный для таблиц. Графики — SVG с сервера. Свои визиты владельца не считаются. Боты на таймлайне появятся с шагом 4 (они видны только в логе nginx), страны — с базой GeoIP на шаге 8.
- [x] **4. Трафик сервера и статус системы** (B6). Чтение JSON-лога nginx с сохранением позиции (переживает ротацию, усечение и перезапуск; ни строки дважды), поминутные суммы, коды ответов, топ URL, поисковики и боты по именам, сканеры (что искали и из каких сетей), всплески 404, p50/p95 по гистограмме. Боты появились на таймлайне обзора. Статус: последняя сборка и шаг сбоя, релиз, данные GitHub, сертификат, который реально отдаёт nginx, нагрузка, память, диски, MySQL, Redis, список проблем. Кнопка «пересобрать» — через systemd path-юнит, без привилегий у веб-сервиса. Статус почты добавится с шагом 7.
- [x] **5a. Заявки: приём** (B10.1–B10.2). Форма на сайте на трёх языках — работает и без JavaScript (обычный POST → страница «спасибо» из релиза с номером заявки). Антиспам по баллам: ловушка, proof-of-work (совместим с ALTCHA), время заполнения, ссылки, стоп-слова; спам сохраняется молча. Лимит 3 заявки в час. Заявка и задачи на уведомления — в одной транзакции; outbox с повторами, идемпотентностью и ожиданием ненастроенного канала. Письмо владельцу и автоответ клиенту (текст + HTML), тестовый SMTP-сервер. Сессия аналитики прикрепляется к заявке. Контракт v1.3.
- [ ] **5b. Заявки в админке** (B10.6). Список и канбан по статусам, карточка с сессией аналитики и лентой переписки, заметки, статусы с историей, ответ клиенту по почте, шаблоны ответов и отказов, воронка и время первой реакции, экспорт CSV, удаление данных по запросу.
- [ ] **5c. Вложения и сроки хранения** (B10.1, B10.7). Вложения к заявке (выключены по умолчанию): проверка типа по сигнатуре, хранение вне веб-корня, выдача только через админку. Обезличивание заявок старше 24 месяцев.
- [ ] **6. Telegram-бот** (B10.3–B10.5). Приглашения, роли, карточка заявки с кнопками, синхронизация статусов у всех получателей, ответы клиенту, заметки, команды, напоминания, дайджест. Клиентский режим-ретранслятор. Webhook через nginx + long polling как запасной вариант.
- [ ] **7. Почта** (B8.9, B10.5). docker-mailserver в `/srv/krokosha/mail`: ящики, DKIM, сертификат Let's Encrypt, без ClamAV. Отправка ответов с `Reply-To: leads+K-0042.<подпись>@…`, приём ответов клиентов по IMAP IDLE, разбор цитат и вложений. Установщик печатает DNS-записи (MX, SPF, DKIM, DMARC, autoconfig) и напоминание про PTR.
- [ ] **8. Эксплуатация.** Гео по IP (локальная база), дневные агрегаты и очистка сырых событий старше 12 месяцев, `backup.sh` (дамп MySQL, почта, настройки; ротация), `krokosha-certwatch`, очистка старых данных по срокам хранения, инструкция по переезду, инструкции по Google Search Console и Bing Webmaster Tools, IndexNow.
