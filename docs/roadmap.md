# Дорожная карта

Что сделано, что дальше и в каком порядке. Обновляется в каждом PR, который закрывает пункт.
Решения и их причины — в [architecture.md](architecture.md), требования — в [brief/MASTER_PROMPT.md](brief/MASTER_PROMPT.md).

**Правила этапа** (решения Дениса от 2026-09-18):

1. На VPS ничего не выкладываем, пока бэкенд не реализован **полностью**.
2. Проверяем локально в Docker: `deploy/docker/staging/staging.sh up` → `https://krokosha.localhost`.
3. Дизайн — после бэкенда (Claude Design работает в `design/` по [design/CLAUDE_DESIGN_PROMPT.md](design/CLAUDE_DESIGN_PROMPT.md)).
4. Хранилище — MySQL + Redis в Docker, все данные в одной директории `/srv/krokosha`.

## Бэкенд — в работе

Каждый пункт — отдельный PR с тестами; после каждого стенд должен подниматься одной командой.

- [x] **1. Основа API.** `krokosha-api`: конфигурация, MySQL (миграции), Redis с деградацией в память, HTTP-сервер, `/api/health`, systemd-юнит, прокси в nginx. Установщик: Docker, контейнеры MySQL и Redis с лимитами памяти, корень данных `/srv/krokosha`, генерация секретов. CI: MySQL и Redis как сервисы. Замер на стенде: MySQL 132 МБ, Redis 4 МБ.
- [ ] **2. Аналитика** (B5). `/api/e`: проверка схемы, дневная соль, усечённый IP, отсев ботов, DNT/GPC, лимиты. `analytics.js` < 3 КБ, читаемый. События: просмотр, глубина скролла, секции, клики по `data-track`, внешние переходы, время на странице, UTM. Страница `/privacy` сверяется с реализацией.
- [ ] **3. Админка: вход и обзор** (B6). Скрытый путь, argon2id, сессии, CSRF, TOTP, лимит попыток + fail2ban. Обзор: таймлайн по часам, «сейчас на сайте», живая лента (SSE), секции, конверсии, источники, гео и устройства. Сессии посетителей. Экспорт CSV. `krokosha-cli admin create`.
- [ ] **4. Трафик сервера и статус системы** (B6). Чтение JSON-лога nginx с сохранением позиции, поминутные агрегаты, коды ответов, топ URL и ботов, сканеры, p50/p95. Статус: последний sync, сертификаты, диск/RAM, версия, кнопка «пересобрать».
- [ ] **5. Заявки** (B10.1–B10.2, B10.6–B10.7). Форма на сайте (работает и без JS), антиспам: honeypot, время заполнения, ALTCHA, лимиты, эвристики. Outbox с повторами. Письмо-уведомление и автоответ клиенту. Админка: список, канбан, карточка с перепиской, шаблоны, воронка, удаление данных по запросу.
- [ ] **6. Telegram-бот** (B10.3–B10.5). Приглашения, роли, карточка заявки с кнопками, синхронизация статусов у всех получателей, ответы клиенту, заметки, команды, напоминания, дайджест. Клиентский режим-ретранслятор. Webhook через nginx + long polling как запасной вариант.
- [ ] **7. Почта** (B8.9, B10.5). docker-mailserver в `/srv/krokosha/mail`: ящики, DKIM, сертификат Let's Encrypt, без ClamAV. Отправка ответов с `Reply-To: leads+K-0042.<подпись>@…`, приём ответов клиентов по IMAP IDLE, разбор цитат и вложений. Установщик печатает DNS-записи (MX, SPF, DKIM, DMARC, autoconfig) и напоминание про PTR.
- [ ] **8. Эксплуатация.** `backup.sh` (дамп MySQL, почта, настройки; ротация), `krokosha-certwatch`, очистка старых данных по срокам хранения, инструкция по переезду, инструкции по Google Search Console и Bing Webmaster Tools, IndexNow.
