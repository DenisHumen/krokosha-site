# Дорожная карта

Что сделано, что дальше и в каком порядке. Обновляется в каждом PR, который закрывает пункт.
Решения и их причины — в [architecture.md](architecture.md), требования — в [brief/MASTER_PROMPT.md](brief/MASTER_PROMPT.md).

**Правила этапа** (решения Дениса от 2026-09-18):

1. На VPS ничего не выкладываем, пока бэкенд не реализован **полностью**.
2. Проверяем локально в Docker: `deploy/docker/staging/staging.sh up` → `https://krokosha.localhost`.
3. Дизайн — после бэкенда (Claude Design работает в `design/` по [design/CLAUDE_DESIGN_PROMPT.md](design/CLAUDE_DESIGN_PROMPT.md)).
4. Хранилище — MySQL + Redis в Docker, все данные в одной директории `/srv/krokosha`.

Каждый пункт — отдельный PR с тестами; после каждого стенд должен подниматься одной командой.

- [x] **1. Основа API.** `krokosha-api`: конфигурация, MySQL (миграции), Redis с деградацией в память, HTTP-сервер, `/api/health`, systemd-юнит, прокси в nginx. Установщик: Docker, контейнеры MySQL и Redis с лимитами памяти, корень данных `/srv/krokosha`, генерация секретов. CI: MySQL и Redis как сервисы. Замер на стенде: MySQL 132 МБ, Redis 4 МБ.
- [x] **2. Аналитика** (B5). `/api/e`: проверка схемы, дневная соль, усечённый IP, отсев ботов, DNT/GPC, лимиты. `analytics.js` < 3 КБ, читаемый. События: просмотр, глубина скролла, секции, клики по `data-track`, внешние переходы, время на странице, UTM. Страница `/privacy` сверяется с реализацией. Сделано: скрипт 2,9 КБ gzip; тест ищет IP и User-Agent во всех таблицах и ключах Redis — их там нет. Гео по IP — в шаге 8.
- [x] **3a. Админка: вход** (B6). Секретный путь (`--admin-path` или случайный), argon2id, сессии в cookie `__Host-`, CSRF, TOTP с QR-кодом, список сеансов, журнал действий. Лимит попыток в API, отдельный лимит nginx на форму входа, fail2ban по логу админки. `krokosha-cli admin list|create|passwd|disable|enable|totp-reset`; установщик создаёт первого администратора (пароль без эха или из файла).
- [x] **3b. Админка: обзор, визиты, экспорт** (B6). Обзор по ref-03: таймлайн (часы или дни, реклама отдельным цветом), «сейчас на сайте», живая лента (SSE), секции по времени и охвату, прокрутка, кольца конверсий, источники, кампании, страницы, языки, клики, устройства, страны; период — день, неделя, месяц, свой диапазон. Визиты: путь посетителя по секциям и кликам. Экспорт CSV, безопасный для таблиц. Графики — SVG с сервера. Свои визиты владельца не считаются. Боты на таймлайне появятся с шагом 4 (они видны только в логе nginx), страны — с базой GeoIP на шаге 8.
- [x] **4. Трафик сервера и статус системы** (B6). Чтение JSON-лога nginx с сохранением позиции (переживает ротацию, усечение и перезапуск; ни строки дважды), поминутные суммы, коды ответов, топ URL, поисковики и боты по именам, сканеры (что искали и из каких сетей), всплески 404, p50/p95 по гистограмме. Боты появились на таймлайне обзора. Статус: последняя сборка и шаг сбоя, релиз, данные GitHub, сертификат, который реально отдаёт nginx, нагрузка, память, диски, MySQL, Redis, список проблем. Кнопка «пересобрать» — через systemd path-юнит, без привилегий у веб-сервиса. Чтение почтового ящика — тоже на этом экране (шаг 7b).
- [x] **5a. Заявки: приём** (B10.1–B10.2). Форма на сайте на трёх языках — работает и без JavaScript (обычный POST → страница «спасибо» из релиза с номером заявки). Антиспам по баллам: ловушка, proof-of-work (совместим с ALTCHA), время заполнения, ссылки, стоп-слова; спам сохраняется молча. Лимит 3 заявки в час. Заявка и задачи на уведомления — в одной транзакции; outbox с повторами, идемпотентностью и ожиданием ненастроенного канала. Письмо владельцу и автоответ клиенту (текст + HTML), тестовый SMTP-сервер. Сессия аналитики прикрепляется к заявке. Контракт v1.3.
- [x] **5b. Заявки в админке** (B10.4, B10.6). Список с поиском и доска по статусам (перетаскивание; без JavaScript — кнопки на карточке). Карточка: лента переписки и истории, заметки, сводка визита, оценка антиспама. «Взять в работу» без гонок — второму сообщается, кто успел. Ответ клиенту тем каналом, который он выбрал (почта — одной цепочкой писем; Telegram — ждёт бота; телефон — запись итога звонка), отметки доставки. Шаблоны ответов и отказов на трёх языках с редактором. Воронка за 30 дней, медиана первой реакции, источники заявок. Экспорт CSV. Удаление данных клиента с подтверждением номером; в журнале — одна строка без персональных данных. Демо-заявки для локального просмотра.
- [x] **5c. Вложения и сроки хранения** (B10.1, B10.7). Вложения к заявке — выключены по умолчанию, включаются одной строкой в `content/site.yaml`: до 3 файлов по 10 МБ, тип определяется по содержимому, хранение вне веб-корня под случайными именами (`0600`), выдача только из админки и только как загрузка; файлы роботов не сохраняются; nginx пропускает большие запросы только на `/api/leads`. Заявки без активности 24 месяца обезличиваются (или удаляются — настройка), спам удаляется через 30 дней, файлы без заявки убирает ежедневная уборка. Контракт v1.4.
- [x] **6a. Бот: основа** (B10.3). Bot API без библиотек (токен не попадает в ошибки и логи), приглашения — одноразовые, на 24 часа, в базе только хэш; привязка по числовому id, роли владелец / участник, отзыв доступа действует сразу; посторонним — приветствие с лимитом, в группах бот молчит. Webhook через nginx (секретный адрес + секретный заголовок, оба из `APP_SECRET`; только сети Telegram; адрес не попадает в лог) и long polling как запасной вариант. `/invite`, `/users`; страница «Бот» в админке; `krokosha-cli bot`; установщик принимает токен из файла или без эха, проверяет его через `getMe` и выдаёт приглашение владельцу.
- [x] **6b. Бот: карточки заявок** (B10.4). Карточка с кнопками приходит всем участникам через outbox (повтор после сбоя — без дублей; пока в боте никого нет, заявки ждут и уходят сразу после входа первого человека). Статус меняется у всех сразу, откуда бы ни пришло изменение — из бота или из админки. Гонка «взять»: второй видит, кто успел. Ответ клиенту: шаблоны на его языке, предпросмотр, «Отправить / Изменить / Отмена»; клиенту с телефоном — запись итога звонка. Отклонение: причина, письмо из шаблона или молча. Заметки, полный текст, история. При удалении или обезличивании заявки бот стирает всё, что писал о ней в чатах.
- [x] **6c. Бот: команды, напоминания, клиенты** (B10.4–B10.5). Клиент приходит по ссылке «Продолжить в Telegram» (одна заявка — один аккаунт), пишет — сообщение попадает в переписку, заявка возвращается в работу, сотрудникам уходит push; ответы сотрудников идут клиенту через бота; клиент видит только номер и статус своей заявки. Ответ идёт тем путём, которым клиент написал последним. `/leads`, `/lead`, `/search`, `/stats`, `/mute`; напоминание о невзятой заявке; утренний дайджест.
- [x] **7a. Почта: сервер** (B8.9, B10.5). docker-mailserver 16 в `/srv/krokosha/mail` (Postfix, Dovecot, Rspamd; без ClamAV): служебный ящик `leads@` и ящик владельца, пароли только хэшами, `krokosha-mailbox`; DKIM-ключ; сертификат сайта с именем `mail.`; запрет отправки от чужого имени и пересылки без пароля; проверка исходящего порта 25; в конце установки — список DNS-записей (A, MX, SPF, DKIM, DMARC, SRV) и напоминание про PTR; автонастройка почтовых программ. Письма клиентам несут `Reply-To: leads+k-0042.<подпись>@…` (HMAC на `APP_SECRET`), конверт — служебный ящик.
- [x] **7b. Почта: входящие** (B10.5). Сервис читает ящик `leads@` по IMAP IDLE (свой небольшой клиент, без библиотек): ответ клиента попадает в переписку заявки по подписанному адресу, цитата отрезана, файлы приняты по правилам формы; письмо известного клиента без номера — в его последнюю заявку; остальное — в раздел «Входящие» админки, где письмо можно отнести к заявке или удалить. Автоответы не будят никого; письмо, которое вернулось, помечает ответ «не доставлено», и сотрудники узнают об этом. После разбора письмо из ящика удаляется — данные живут только в заявке. Статус чтения ящика — на экране «Статус».
- [x] **8. Эксплуатация.** `backup.sh` каждую ночь: дамп MySQL, настройки и секреты, сертификаты, письма и файлы заявок жёсткими ссылками между копиями (месяц копий — место одной), ротация 7 дневных + 4 недельных, копия на другую машину по `BACKUP_RSYNC_TO`; `restore.sh` — восстановление на установленный сайт, в том числе на новом сервере (пароли базы остаются свои, всё остальное возвращается: секрет подписи, путь админки, ящики и DKIM, бот с адресом Bot API, ключи). `krokosha-certwatch` раз в сутки смотрит на сертификаты, которые реально отдают nginx и почта, продлевает заранее и зовёт владельца, когда не вышло. Оповещения владельца — `krokosha-cli alert` через outbox (почта + Telegram, один повод — одно письмо в сутки). Дневные итоги статистики (`analytics_daily*`) и удаление сырых событий старше `ANALYTICS_KEEP_MONTHS` (12) только там, где итоги есть; обзор старого периода — из итогов. Гео по IP: `internal/geo` по локальной базе — DB-IP City Lite без ключей (`krokosha-dbip.timer`, раз в месяц; ссылка «IP Geolocation by DB-IP» внизу админки) или GeoLite2 (`--maxmind-account`, `--maxmind-key-file`, `geoipupdate` по таймеру дважды в неделю), названия стран по-русски, город на карточке визита. IndexNow после каждого релиза — только изменившиеся страницы (сборка воспроизводима), ключ отдаётся сайтом, `--no-indexnow`. Мета-теги подтверждения для Google Search Console и Bing Webmaster Tools (`seo.verification`), инструкции по ним и по переезду — в `deploy/README.md`. Статус системы: копии, сертификаты, база GeoIP. Стендовый тест: копии и восстановление после «потери сервера», сертификаты и оповещение, IndexNow и GeoIP против притворных сервисов.
