# Быстрые ответы: шаблоны, подбор по контексту, файлы

Поле ответа в разговоре («Заявки» в админке) предлагает готовые ответы на типовые вопросы
клиента: сколько стоит, что вы умеете, какие работы уже были, когда сможете начать, сможете ли
помочь. Первыми — чипами над полем — показываются три шаблона, которые лучше всего подходят
разговору, остальные — в списке «Все шаблоны» с поиском.
Несколько шаблонов складываются в один ответ. Фото, видео и документы шаблона уходят клиенту
вместе с текстом.

Код: `api/internal/leads/templates.go` (хранилище), `rank.go` (подбор), `api/internal/admin/quick.go`
(редактор), `api/internal/admin/leads.go` + `messenger.go` + `templates/leads.html` (ответ в разговоре),
миграция `api/migrations/0018_quick_replies.sql`.

## Пул шаблонов

Шаблоны — таблица `reply_templates`: вид (ответ или отказ), язык (ru/uk/en), название, текст и
поля для подбора:

| Поле | Что значит |
|---|---|
| `category` | что шаблон отвечает: приветствие, о себе, умения, работы, стоимость, сроки, помощь, варианты, детали, созвон, как работаю, оплата, предложение, полезное, поддержка, конфиденциальность, напоминание, завершение; пусто — «другое» |
| `keywords` | слова клиента через запятую: начала слов и фразы (`цен, стоим, сколько стоит`) |
| `directions` | для каких направлений формы; пусто — для любых |
| `moment` | когда подходит: в любой момент, первый ответ, в разговоре, клиент молчит, заказ выполнен |
| `used_count`, `used_at` | сколько раз и когда отправлен |

Стартовый набор — 15 шаблонов на каждом языке. Вместе с четырьмя шаблонами из миграции `0006`
получается 19. Тексты написаны от первого лица, как сайт, и без своего приветствия, поэтому
складываются друг с другом: «Приветствие» + «Стоимость» + «Сроки». Факты в текстах (с 2017 года,
часовой пояс Киева, стек) взяты из `content/site.yaml`.

Миграция `0018` не трогает данные владельца:

- новый шаблон добавляется, только если шаблона с таким же названием на этом языке ещё нет;
- у шаблонов из `0006` заполняются только новые поля (категория, слова, момент), тексты не
  меняются;
- шаблон, который владелец переименовал, остаётся без категории и слов, пока их не заполнят в
  редакторе.

Подстановки в тексте:

| Метка | Что подставляется |
|---|---|
| `{name}` | имя клиента |
| `{id}` | номер заявки (`K-0042`) |
| `{site}` | сайт на языке клиента |
| `{account}` | заявка в личном кабинете |

## Как разговор выбирает первые три

Подбор — правила без модели и без внешних сервисов (`leads.Rank`). Под каждой подсказкой
написано, почему она поднялась, например «стоимость» · первый ответ.

1. **Слова клиента.** Каждое слово шаблона ищется в тексте клиента после нормализации: нижний
   регистр, `ё` → `е`, один вид апострофа. Начало слова находит слово целиком (`стоим` →
   «стоимость»), фраза ищется как слова подряд. Слова до трёх букв (`кп`, `nda`, `hi`) ищутся
   только целиком: `кп` не найдётся в «КПД». Фраза весит в 1,5 раза больше слова.
2. **Последнее сообщение важнее описания заявки.** Слово из последнего сообщения клиента даёт
   3 балла, из темы и описания заявки — 1,5. Учитывается не больше трёх совпадений из сообщения
   и двух из описания.
3. **Момент разговора.** Он вычисляется по заявке:
   - первый ответ — если ещё ничего не ответили;
   - клиент молчит — если последнее сообщение наше, статус «Ждём клиента» и прошло 48 часов;
   - заказ выполнен — если статус «Готово»;
   - иначе — в разговоре.

   Шаблон своего момента получает +2, чужого — −3; шаблон «в любой момент» не получает ничего.
4. **Направление.** Шаблон для направления заявки получает +1,5, для другого направления — −2.
5. **Короткий первый вопрос** (меньше 120 символов) поднимает шаблон «Нужны детали» на +1.
6. **Уже отправленные** в этой заявке шаблоны опускаются на −6: они поднимутся, только если
   больше ничего не подходит.
7. **Привычка.** При равенстве выше тот, что отправляют чаще, — не больше +0,5.

В первую тройку попадает лучший шаблон каждой категории: два приветствия рядом не встанут.
Шаблоны с нулём баллов и меньше в тройку не попадают — тогда подсказок меньше трёх или нет вовсе.
Остальные шаблоны языка клиента собраны в списке «Все шаблоны» по категориям, с фильтром по
словам.

Если подсказки промахиваются, лучше всего поправить слова клиента у нужного шаблона в
редакторе. Подбор работает на тех же словах.

## Ответ в разговоре

- Щелчок по шаблону добавляет его текст в поле ответа через пустую строку, а файлы шаблона — в
  список файлов над полем. Файл можно снять галочкой. Текст можно править перед отправкой.
- «+ Файл» — любые фото, видео и документы с компьютера, до 10 файлов на ответ вместе с
  файлами шаблонов.
- Enter отправляет, Shift+Enter — новая строка; поле растёт с текстом до 160 px.
- «Ответ / Заметка» — то же поле пишет внутреннюю заметку: клиент её не видит, файлы к ней не
  прикрепляются.
- «→ почта · Telegram · кабинет» — куда уйдёт ответ; канал можно снять галочкой.
- Без JavaScript всё работает ссылками: шаблон открывает разговор с готовым черновиком
  (`?template=N`).
- Ответ помнит, из каких шаблонов собран (`lead_messages.templates`). Отправленный шаблон
  помечается «уже отправлен» и опускается в подборе этой заявки.
- В заявке с телефоном ответ — это итог звонка: файлы к нему не прикрепляются.

Файлы ответа — те же вложения заявки (`lead_attachments`): они видны в переписке и удаляются
вместе с заявкой. Файл шаблона попадает в ответ жёсткой ссылкой (копией, если ссылка
невозможна). Поэтому удаление шаблона не трогает отправленные ответы, а удаление заявки не
трогает шаблон.

## Как файлы доходят до клиента

Ответ уходит везде, где клиента можно найти (`leads.Reach`, [telegram.md](telegram.md)). Файлы идут
вместе с ним в каждое место: в Telegram — альбомом, письмом — вложениями, в кабинете — рядом с ответом.

**Telegram** (`api/internal/telegram/answers.go`). Порядок частей:

1. Текст, кусками до 3700 символов.
2. Фото и видео одним альбомом (до 10 штук); одно фото или видео уходит отдельным сообщением.
3. Документы — альбомом документов или по одному.

Как отправка переживает сбои:

- **Досылка.** Каждая дошедшая часть записывается в `lead_messages.sent_parts`. Повтор после
  сбоя (Telegram занят, оборвалась связь) отправляет только недостающие части: клиент не
  получит текст дважды.
- **Кэш `file_id`.** Файл загружается в Telegram один раз. Потом он уходит по `file_id`, который
  хранится в `telegram_uploads` по sha256 содержимого. Поэтому фото шаблона во втором ответе
  не загружается заново. Если Telegram больше не знает id (например, у бота новый токен), файл
  загружается ещё раз.
- **Фото, которое Telegram не принял** (слишком длинное или широкое), и видео, которое он не
  прочитал, уходят документами.
- **Окончательный отказ.** Когда повторять бессмысленно — клиент заблокировал бота, файл пропал
  с диска, Telegram отказывает окончательно, — ответ помечается «не доставлено», и команда
  получает уведомление.
- **Время на отправку.** Ответу с файлами outbox даёт больше времени, чем обычному сообщению:
  30 секунд плюс 2 секунды на мегабайт, но не больше 5 минут (`outbox.Patient`). Остальные
  задачи в это время ждут.

**Почта** (`api/internal/leads/notify.go`). Файлы уходят вложениями, вместе до 15 МБ: в base64
это около 20 МБ, меньше 25 МБ, которые пропускает почтовый сервер сайта. Файлы, которые не
поместились, письмо называет по имени и даёт ссылку на заявку в кабинете. Вход в кабинет — по
тому же адресу почты, заявки с этим адресом появятся в кабинете сами.

**Личный кабинет** (`api/internal/clients/http.go`). Файлы видны прямо в переписке:

- фото и видео ответа — миниатюрой и плеером;
- документы и всё, что прислал сам клиент, — ссылкой на скачивание.

Отдаёт их `GET /api/account/leads/<K-0042>/files/<id>` — только владельцу заявки и только со
страниц сайта (`nosniff`, `CSP: sandbox`). Уведомление об ответе в кабинете приходит в Telegram
аккаунта вместе с файлами. Письмо-уведомление только называет число файлов.

## Бот

Кнопки ответа в боте упорядочены тем же подбором, что и разговор в админке: восемь шаблонов, первые три
помечены ★. У шаблона с файлами на кнопке их число: «Примеры работ · 📎2». Предпросмотр
называет файлы, которые уйдут вместе с ответом. «✏️ Изменить» меняет только текст, файлы
шаблона остаются.

## Редактор шаблонов

«Шаблоны» в меню: вкладки «Ответы» и «Отказы», три языка, поиск по названию, тексту и словам. В
карточке шаблона есть:

- категория, момент и направления;
- слова клиента;
- счётчик отправок;
- файлы.

Какие файлы можно прикрепить:

| Тип | Лимит |
|---|---|
| фото JPG и PNG | до 10 МБ |
| видео MP4 | до 50 МБ |
| документы PDF, DOCX и TXT | до 20 МБ |
| всего у шаблона | 10 файлов |

Тип определяется по содержимому, а не по имени файла. Лимиты — это лимиты Telegram Bot API.

## Где лежат файлы

- Файлы шаблонов: `<данные>/attachments/templates`, файлы ответов — рядом с файлами заявок в
  `<данные>/attachments`. Имена случайные, права `0600`: читать их может только сервис.
- Ночная уборка (`retention.go`) удаляет из папки шаблонов файлы, о которых база не знает.
  Файлам больше суток: это остатки прерванной загрузки.
- Бэкап копирует `attachments` целиком (`rsync --hard-links`): жёсткие ссылки остаются ссылками,
  место не удваивается.
- `telegram_uploads` хранит только sha256 и id файла у Telegram. Строка удаляется ночной
  уборкой, как только ни в одной заявке и ни в одном шаблоне не осталось файла с таким
  содержимым.

## nginx

Формы админки принимают до 64 КБ. Формы с файлами идут на отдельный путь
`<ADMIN_PATH>/upload/`: там до 110 МБ и не больше двух загрузок одновременно с одного адреса
(`deploy/nginx/site-https.conf.tmpl`). nginx сначала принимает тело целиком (буферизует: медленная
загрузка не держит API), затем API проверяет сеанс и происхождение запроса, разбирает форму и
сверяет CSRF-токен. Не форма с файлами ограничена размером маленькой формы ещё до чтения.
Страница проверяет лимиты сразу после выбора файлов: файл больше своего предела,
больше 10 файлов или больше 110 МБ вместе. Сообщение появляется под полем, форма не уходит.
Сервер проверяет всё ещё раз, по содержимому файлов.

Проверки установки: `deploy/ci/test-install.sh` загружает файл больше обычной формы в шаблон
через nginx и проверяет, что остальная админка по-прежнему принимает только маленькие формы.
