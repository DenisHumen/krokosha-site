# Карта интернета (`/map`)

Страница со всеми сетями интернета (автономными системами, AS) и связями между ними. Введите два адреса — карта нарисует, как между ними вероятнее всего пойдут пакеты: сеть за сетью, где сети встречаются (точка обмена трафиком или дата-центр), какие у них там порты и сколько займёт дорога.

Три вида с плавным переходом между ними:

- **карта** — точечная карта мира в стиле сайта (проекция Equal Earth);
- **ядро** — как у CAIDA: крупнейшие сети в центре, мелкие по краю, угол — долгота сети;
- **глобус** — ортографическая проекция, вращается сама, пока её не трогают.

Разметка и тексты страницы описаны в [contract.md §8](contract.md#8-v16-карта-интернета).

## Что готово и что дальше

| Этап | Что | Статус |
|---|---|---|
| A | Модель на Go (`api/internal/netmap`), CLI `krokosha-cli netmap`, страница `/map` с тремя видами, маршрут по модели, тесты | этот PR |
| B | Хранение в MySQL с ежесуточным обновлением (пишутся только изменения), API в проде, кэш маршрутов и лимиты в Redis, nginx, установщик, строка в статусе | дальше |
| C | Замеры: traceroute с сервера (реальные хопы, IP, задержки, потери по каждому хопу) и RIPE Atlas — из сети отправителя | после B |

До этапа B на проде страница показывает «Данные карты ещё не готовы»: сервер их пока не строит.

## Как устроено

```
раз в сутки (этап B — таймер systemd)
  krokosha-cli netmap fetch  →  /var/lib/krokosha/netmap/data/   источники как есть
  krokosha-cli netmap build  →  /var/lib/krokosha/netmap/public/  overview.json + overview-<хэш>.bin
                                                                  (nginx отдаёт как /netmap/data/)
API (krokosha-api)
  модель в памяти  →  /api/net/route, /api/net/as/{asn}, /api/net/search, /api/net/me

браузер
  /netmap/land.bin + /netmap/data/overview.json → overview-<хэш>.bin → WebGL
  форма маршрута → /api/net/route → таблица + анимация пути
```

### Модель (`api/internal/netmap`)

| Файл | Что делает |
|---|---|
| `link.go`, `asn.go` | связь двух AS, её вид и откуда она известна; разбор файла CAIDA |
| `mrt.go` | чтение снимков RouteViews (MRT TABLE_DUMP_V2, в том числе ADD-PATH): пути AS, из них — связи |
| `prefix.go` | диапазоны адресов → AS (двоичный поиск), имена и страны AS из iptoasn |
| `peeringdb.go` | загрузка PeeringDB (по объекту на файл, пауза между запросами) и чтение |
| `model.go` | граф связей (CSR), конусы клиентов, ранги, точки обмена и дата-центры |
| `place.go` | где сеть на карте: по её адресам (GeoIP), иначе по её дата-центрам, иначе рядом с соседями |
| `route.go` | маршрут и где сети встречаются |
| `overview.go` | обзор для браузера (формат `KNM1`) |
| `sources.go` | скачивание и чтение всех источников |
| `http.go` | API |

**Связи.** Основа — CAIDA, где у каждой связи есть вид. Связи из свежих таблиц RouteViews, которых у CAIDA нет, добавляются с видом «неизвестно». Путь AS с AS_SET, конфедерациями, частными номерами или петлёй обрывается на первом таком месте; повторы одной AS (prepend) схлопываются.

**Маршрут.** Для каждой AS назначения строится дерево лучших путей до неё (очередь по корзинам, как у Дейкстры), с правилами экспорта BGP: путь, полученный от провайдера или пира, дальше отдаётся только клиентам. Оценка пути — `2 × длина + штраф`, где шаг к клиенту стоит 0, к пиру 1, к провайдеру 2. Чистая модель Гао–Рексфорд не подошла: утёкшие «клиентские» связи в данных тянули маршруты через полмира. При равенстве предпочтение — сеть с бо́льшим конусом.

**Где сети встречаются.** Общая точка обмена или общий дата-центр из PeeringDB, если крюк от текущего места не больше 1 500 км. Иначе — догадка: клиент встречает провайдера «здесь», провайдер клиента — у клиента дома, пиры — здесь, если другой не совсем мелкий. Скорости портов — из PeeringDB (`netixlan.speed`), только для точек обмена.

**Anycast.** Адреса известных anycast-резолверов (Cloudflare, Google, Quad9, OpenDNS) не имеют одного места: конец маршрута — ближайшее к отправителю (не дальше 3 000 км) присутствие сети назначения.

**Задержка** — оценка, не замер: `RTT ≈ 2 × 1,3 × расстояние / 200 км/мс + 0,2 мс на каждую сеть`. Свет в волокне проходит около 200 км за миллисекунду, кабели длиннее прямой примерно на треть. **Потери** можно только измерить — до этапа C в таблице «не измерено».

### Обзор (`KNM1`)

Little-endian, секции выровнены на 4 байта, чтобы браузер читал их типизированными массивами без копирования. Сети отсортированы по рангу (крупнейшие первыми), и ядро и имена — это первые N из них.

| Часть | Содержимое |
|---|---|
| заголовок, 16 × u32 | `"KNM1"`, версия, время сборки (unix), число сетей на карте, точек обмена, пучков, связей ядра, сетей в ядре, сетей с именами, всего связей, всего сетей, диапазонов IPv4, IPv6, длина текста, 0, 0 |
| сети | `asn u32[]`, `lat i16[]`, `lon i16[]` (сотые градуса), `size u8[]` (разрядность конуса), `degree u8[]`, `type u8[]`, `country u8[]` |
| точки обмена | `lat i16[]`, `lon i16[]`, `members u16[]`, `capacity u32[]` (Гбит/с) |
| пучки | связи между клетками 2° × 2°, 5 000 крупнейших: `lat1, lon1, lat2, lon2 i16[]`, `links u32[]` |
| ядро | связи между 1 000 крупнейших сетей: `a u16[]`, `b u16[]`, `rel i8[]` |
| текст | JSON: `countries[]`, `names[]` (3 000 крупнейших), `exchanges[[name, city, country]]`, `types[]` |

Файл называется по хэшу содержимого и кэшируется надолго; `overview.json` (манифест) — коротко. Сборка оставляет три последних файла, чтобы страница, открытая до обновления, догрузилась.

Обе стороны формата проверяются на одном файле: Go-тест `TestOverviewGolden` пишет обзор тестового мира в `web/tests/fixtures/netmap-overview.bin`, а тесты страницы читают его своим декодером.

### Страница (`web/src/scripts/netmap/`)

| Файл | Что делает |
|---|---|
| `data.ts` | чтение `KNM1` и `KLD1` |
| `projection.ts` | Equal Earth, ядро, ортографическая проекция; камера |
| `renderer.ts` | WebGL 1 без библиотек: один вершинный шейдер ставит точку в два вида и смешивает их — так работает переход между видами |
| `layers.ts` | слои: суша, сети, точки обмена, пучки, ядро, связи выбранной сети, след маршрута |
| `panel.ts` | таблица маршрута и карточка сети — только `textContent`: имена сетей приходят из реестров, за них никто не ручается |
| `map.ts` | загрузка, мышь, касания, клавиатура, форма, адрес страницы |

Без WebGL видна причина, а форма и таблица маршрута работают. При `prefers-reduced-motion` переходы и анимация пакета не играют.

## API

| Запрос | Ответ | Лимит в минуту | Кэш |
|---|---|---|---|
| `GET /api/net/route?from=&to=` | маршрут | 30 | 10 мин |
| `GET /api/net/as/{asn}` | сеть: размер, соседи (до 16 каждого вида), точки обмена | 60 | 1 ч |
| `GET /api/net/search?q=` | до 12 сетей по номеру или имени | 60 | 1 ч |
| `GET /api/net/me` | адрес посетителя, его сеть и место | 30 | `no-store` |

Ошибки — `{"error": "<код>"}`: `bad_address`, `private_address` (частные сети, CGNAT, документационные и служебные диапазоны), `not_routed`, `no_path`, `unknown_as`, `busy` (429), `not_ready` (503 — модель ещё не построена).

**Приватность.** `/api/net/me` возвращает посетителю его собственный адрес и ничего не сохраняет. API не записывает адреса из формы. Журнал nginx (30 дней, как для всего сайта) пишет адрес запроса целиком, со строкой `?from=&to=`, — на этапе B для `/api/net/` в журнал пойдёт только путь. Ссылка на маршрут хранит `from=me` вместо адреса, так что, поделившись ею, человек не раскрывает свой IP.

## Разработка

```bash
cd api
go run ./cmd/krokosha-cli netmap fetch --data /tmp/netmap/data
go run ./cmd/krokosha-cli netmap build --data /tmp/netmap/data --geoip /path/to/dbip-city-lite.mmdb --out /tmp/netmap/out
go run ./cmd/krokosha-cli netmap route --data /tmp/netmap/data --geoip ... 1.1.1.1 46.175.147.165
go run ./cmd/krokosha-cli netmap serve --data /tmp/netmap/data --geoip ... --out /tmp/netmap/out --me 95.46.140.1
```

Флаги — до адресов. `serve` заменяет API на время разработки (`127.0.0.1:8091`); `--me` — какой адрес считать адресом посетителя. Страница с ним:

```bash
NETMAP_DEV_API=http://127.0.0.1:8091 npm --prefix web run dev
```

С `NETMAP_DEV_API` dev-сервер Astro проксирует `/api/net` и `/netmap/data` и не требует `/` в конце адресов.

Тесты: `go test ./internal/netmap` (с `-update` — переписать обзор тестового мира для тестов страницы), `npm test` (`tests/unit/netmap.test.ts`), `npx playwright test tests/e2e/map.spec.ts`.
