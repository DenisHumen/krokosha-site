## 2. Что изменилось относительно брифа (контракт v1.1–v1.4)

0. **Три языка: EN (основной, `/`), UA (`/uk/`), RU (`/ru/`).** Переключатель — в верхней навигации (и в мобильном меню), данные — `site.i18n.locales`, трек `lang-<code>`. Любой видимый текст берётся из `mock/<lang>/site.json`, включая подписи формы, ошибки, 404 и `aria-label`. Плейсхолдеры `{id}`, `{hours}`, `{email}`, `{privacy_link}`, `{year}` в превью подставляй сам (примеры: `#K-0042`, `24`, `denis@krokosha.xyz`). Подробно — contract.md §6.

1. **Проекты: показываются все публичные репозитории**, но с разной подачей. У каждого есть `tier`:
   - `featured` (6 шт.) — крупные карточки со всеми полями;
   - `standard` (8 шт.) — карточки поменьше;
   - `compact` (8 шт., включая 5 архивных) — плотный список, свёрнутый под кнопкой «Все репозитории».

   Архивные помечены `archived: true` → нужна метка «архив». Порядок в массиве уже правильный, не пересортировывай.
2. **`mock/<lang>/site.json`** — все тексты страницы. Никакой текст не хардкодится в разметке: ставь `data-slot="site.hero.headline.strong"` и т.п.
3. **`data-field`** — поля внутри повторяющихся компонентов (пример в contract.md §3).
4. **`stale: true`** в projects.json → показать `site.projects.error_note` (GitHub недоступен, показан кэш).
5. Новые секции для аналитики: `stats`, `curtain`. Новые треки: `cta-discuss`, `form-submit`, `projects-show-all`, `form-continue-telegram`.
6. **Форма заявки уже работает** (contract.md §7) — это единственное место, где разметка связана с бэкендом напрямую. Посетитель без JavaScript отправляет её обычным POST, поэтому **имена полей (`name`), `method`/`action`, блоки сообщений с их `id` и метки `%%…%%` на странице `thanks` менять нельзя**; всё остальное — вёрстка, порядок, анимации — твоё. Рабочий образец: `web/src/components/ContactForm.astro`, `web/src/pages/[...lang]/thanks.astro`, поведение — `web/public/assets/form.js` (в нём нет ничего о внешнем виде, подключается как есть). После успешной отправки на `document` приходит событие `krokosha:lead` — на него можно повесить анимацию. Поле «Файлы» (`name="files"`, contract.md §7, v1.4) есть в разметке только при `form.attachments: true` — по умолчанию выключено, но состояние с полем и его ошибками (`too_many_files`, `file_too_big`, `file_type`) нужно нарисовать.

## 5. Технические рамки

- **Технологии:** HTML/CSS/JS или React/TSX без платных зависимостей. Анимации — CSS, GSAP + ScrollTrigger, Lenis. Hero — Canvas 2D или WebGL (Three.js). Персонажи — Lottie/Rive/SVG.
- **Производительность важнее эффектов.** Цель — Lighthouse ≥ 95 на мобильном, LCP < 2.5 с, CLS < 0.1, INP < 200 мс. Тяжёлое грузится после `load`/`idle`. Число частиц адаптивное (десктоп ~6–10 тыс., мобильный ~2–3 тыс.), при просадке FPS — автоматически меньше.
- **`prefers-reduced-motion`**: руки статичны, инерционный скролл выключен, пасхалки не бегают сами.
- **Адаптив:** mobile-first, 360px → 1920px+. Проверить 360, 768, 1024, 1440, 1920.
- **Доступность:** контраст WCAG AA в обеих темах, видимый фокус, alt-тексты, семантические заголовки (один `h1` — в hero).
- **Шрифты:** Google Fonts / Fontsource, с кириллицей, `font-display: swap`. Обязательно проверить украинские буквы **ґ Ґ є Є і І ї Ї** и апостроф `'` — в обоих начертаниях (гротеск и моно). Для dot-matrix цифр достаточно цифр и латиницы.
- **Длина строк:** основной язык — английский, но украинский и русский в среднем на 20–40 % длиннее. Проверять каждую секцию на всех трёх языках; вёрстка должна выдерживать строки в 1.5 раза длиннее английских.
- **Данные:** в `preview/` подгружай mock через `fetch("../../mock/" + lang + "/profile.json")` и т.д., язык — из `?lang=en|uk|ru` (по умолчанию `en`). Так превью совпадает с тем, что увидит сборка. Открывать через локальный сервер из корня репозитория (`npx serve .`), с `file://` fetch не работает.

## 6. Чего не делать

- Не копировать с референсов логотипы, тексты, бренды и точную вёрстку. Руки — своя генерация.
- Не придумывать факты о Денисе, цифры и проекты. Всё берётся из `mock/`, `TODO` оставляется как есть.
- Никакой «хакерской» зелени на чёрном и стокового «developer portfolio».
- Не трогать ничего вне `design/`. Если нужно поменять формат данных — описать в PR, контракт меняет бэкенд.
- Не ссылаться на `docs/brief/refs/` из своих файлов (папка будет удалена).

## 7. Как сдавать

1. **Предпочтительно:** pull request в `main`, только файлы в `design/`. В описании PR — что сделано, скриншоты светлой и тёмной темы, мобильный и десктоп.
2. **Альтернатива:** ZIP со структурой `design/`, который передаётся бэкенду и раскладывается как есть.
3. Каждая сдача — запись в `design/handoff/CHANGELOG.md`.

**Готово, когда:**
- [ ] `tokens.css` покрывает обе темы, в компонентах нет «магических» цветов и размеров;
- [ ] все секции страницы + 404 / privacy / thanks / play;
- [ ] каждый повторяющийся элемент — один шаблон с `data-field`;
- [ ] все `data-slot` / `data-track` / `data-section` из contract.md расставлены;
- [ ] все состояния формы и проектов (`stale`, пустые приватные);
- [ ] переключатель языка; каждая секция проверена на EN / UA / RU;
- [ ] reduced-motion и фолбэк без WebGL;
- [ ] превью в `preview/` открываются на mock-данных без сборки;
- [ ] спецификации анимаций в `handoff/` (тайминги, кривые, триггеры скролла).
